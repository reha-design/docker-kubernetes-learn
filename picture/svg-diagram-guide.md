# SVG 학습 도식 작성 가이드

이 저장소의 `picture/*.svg`는 전부 이 규칙으로 만들어졌다. 새 그림을 추가하거나 다른 모델로
비슷한 결과를 재현하고 싶을 때 이 문서를 그대로 프롬프트에 붙여넣으면 된다.

## 0. 전제 조건 (가장 중요)

- **완전히 독립적인(self-contained) SVG 파일**로 만든다. GitHub 마크다운 미리보기, 로컬 브라우저,
  VS Code 미리보기 어디서 열어도 똑같이 보여야 한다.
- 이 말은 곧 **외부 CSS 클래스, `<style>` 태그의 CSS 변수, 외부 폰트, 외부 스크립트를 쓰지 않는다**는
  뜻이다. 모든 색상은 `fill="#RRGGBB"` / `stroke="#RRGGBB"`로 태그에 직접 박아 넣는다.
- 배경은 항상 흰색 `<rect>`를 맨 앞에 깐다 (GitHub 다크 모드에서 텍스트가 안 보이는 사고 방지).

```xml
<rect x="0" y="0" width="680" height="392" fill="#FFFFFF"/>
```

## 1. 캔버스 크기와 여백

- `viewBox="0 0 W H"` 기준, 폭은 보통 **680px** (노트 본문 폭에 맞음). 높이는 내용에 맞춰 가변.
- 안전 여백: 좌우 **x=40 ~ x=640**. 이 밖으로 도형이 나가면 마크다운 렌더링 시 잘릴 수 있다.
- 도형 배치 전에 **좌표를 손으로 먼저 계산**한다. 특히:
  - 박스끼리 겹치지 않는지
  - 텍스트가 박스 폭을 넘지 않는지 (아래 3번 참고)
  - 화살표가 다른 박스를 가로지르지 않는지
- 다 그리고 나서 검증하지 말고, **그리기 전에 좌표 표를 만들어서** 겹침을 걸러낸다.

## 2. 색상 팔레트

원색을 쓰지 않고 아래 램프(50=배경, 600=테두리/보조텍스트, 800=진한 텍스트)만 쓴다.
**한 그림에 색이 있는 램프는 최대 2개**, 나머지는 회색(중립)으로 처리한다. 색은 항상 "의미"를
가져야 한다 (아무 박스나 예쁘라고 칠하지 않는다).

| 램프 | 50 (배경) | 600 (테두리/보조) | 800 (진한 텍스트) | 의미로 쓸 때 |
|---|---|---|---|---|
| gray (중립) | `#F1EFE8` | `#5F5E5A` | `#444441` | 구조적 컨테이너, 중간 단계, "그냥 하나의 단계" |
| teal (청록) | `#E1F5EE` | `#0F6E56` | `#085041` | 네트워크/라우팅/정상 동작 (Service, CoreDNS, PVC) |
| coral (산호) | `#FAECE7` | `#993C1D` | `#712B13` | 문제/실행 단위/주의 (Pod, 실패, 삭제됨) |
| amber (호박) | `#FAEEDA` | `#854F0B` | `#633806` | 경고/한계 도달 (Max 도달, 상한선) |

박스 채우기는 50, 테두리는 600, 제목 텍스트는 800, 부제 텍스트는 600을 쓴다.

```xml
<rect fill="#E1F5EE" stroke="#0F6E56" stroke-width="1"/>
<text fill="#085041">제목</text>
<text fill="#0F6E56">부제</text>
```

## 3. 타이포그래피

- 폰트: `font-family="'Malgun Gothic', 'Apple SD Gothic Neo', Arial, sans-serif"` (한글 필수 지원).
- 제목: `font-size="14" font-weight="500"`. 부제: `font-size="12"` (weight 없음).
- **글자 수 계산**: 박스 안쪽 여백은 `박스폭 - 24px`. 한글+영문 혼합 텍스트는 대략
  `글자수 × 7~9px`(12~14px 폰트 기준)로 어림잡아, 이 값이 안쪽 여백을 넘지 않게 글을 줄인다.
  넘칠 것 같으면 문구를 줄이거나(예: "IP 고정 + 부하 분산" → "IP 고정 + 부하분산") 박스를 넓힌다.
- 텍스트 중앙 정렬: `text-anchor="middle"`로 박스 가로 중심 x에 맞춘다.
- 세로 위치(centered) 공식 — `dominant-baseline` 대신 **rect의 y값 기준 오프셋**으로 직접 계산한다
  (독립 파일에서는 `dominant-baseline="central"`이 일부 뷰어에서 어긋나는 경우가 있어 피한다):
  - 한 줄짜리 박스(높이 44): `text y = rect_y + 27`
  - 두 줄짜리 박스(높이 56~64): `제목 y = rect_y + 0.40 × 높이`, `부제 y = rect_y + 0.74 × 높이`
    (예: 높이 64면 제목 +26, 부제 +47)

## 4. 박스(노드) 규칙

```xml
<rect x="230" y="100" width="220" height="56" rx="10" fill="#E1F5EE" stroke="#0F6E56" stroke-width="1"/>
<text x="340" y="123" text-anchor="middle" font-size="14" font-weight="500" fill="#085041">Service</text>
<text x="340" y="143" text-anchor="middle" font-size="12" fill="#0F6E56">IP 고정 + 부하 분산</text>
```

- 모서리 둥글기: 일반 노드 `rx="8~10"`, 큰 컨테이너(구조도의 외곽 박스) `rx="20"`.
- 노드 사이 가로 간격은 최소 **20px**, 세로 간격(화살표 포함)은 **16~40px**.
- 큰 컨테이너 안에 작은 노드를 넣을 땐 안쪽 여백 **20px**를 확보한다
  (컨테이너 x=40, width=600이면 안쪽은 x=60~620).
- 컨테이너 라벨(제목)은 왼쪽 상단에 `text-anchor` 없이(기본 start) 배치:
  `title y = 컨테이너_y + 28`, `subtitle y = 컨테이너_y + 48`.

## 5. 화살표

화살촉은 `<marker>`를 한 번 정의해서 재사용한다. 이 블록을 그대로 복사해서 쓴다:

```xml
<defs>
  <marker id="arrow" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="6" markerHeight="6" orient="auto-start-reverse">
    <path d="M2 1L8 5L2 9" fill="none" stroke="#5F5E5A" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/>
  </marker>
</defs>
<line x1="340" y1="86" x2="340" y2="126" stroke="#5F5E5A" stroke-width="1.5" marker-end="url(#arrow)"/>
```

- 화살표 색은 항상 중립 회색(`#5F5E5A`), 굵기 `1.5`.
- **화살표에 라벨을 달지 않는 게 기본값.** 박스의 제목/부제만으로 관계가 설명되면 라벨 생략.
  방향이 여러 갈래이거나 "왜 이 화살표인지"가 박스 텍스트만으로 안 풀릴 때만 짧은
  라벨(`font-size="12"`, 회색)을 화살표 옆(선과 안 겹치게, 오른쪽에 살짝 띄워서)에 추가한다.
- 화살표는 박스 가장자리에서 시작/끝나야 하고, 다른 박스를 가로질러 지나가면 안 된다
  (지나가는 경로에 다른 도형이 있는지 좌표로 미리 확인).

## 6. 다이어그램 유형별 레이아웃 패턴

이 저장소에서 실제로 쓴 3가지 패턴:

1. **선형 플로우** (예: `service-dns.svg`, `hpa-max-limit.svg`) — 박스 3~4개를 가로로 나열,
   사이를 화살표로 연결. 노드 하나당 "무엇을 하는 단계인가"가 제목+부제로 드러나야 한다.
2. **구조 컨테이너** (예: `pod-deployment-service.svg`, `statefulset-vs-deployment.svg`) —
   회색 큰 박스(컨테이너) 안에 색깔 있는 작은 박스 여러 개. 컨테이너 = "이게 무엇을 관리/포함하는가",
   안의 박스 = "실제 실행 단위".
3. **2열 비교** (예: `dockerfile-layer-cache.svg`, `requests-limits-pending-oom.svg`,
   `readiness-vs-liveness.svg`) — "나쁜 예 vs 좋은 예" 또는 "① vs ②"를 좌우 또는 상하로 나란히 배치.
   같은 단계는 같은 y(또는 x)에 맞춰야 비교가 한눈에 들어온다.

어떤 개념이든 그리기 전에 **이 3가지 중 어느 패턴에 가장 잘 맞는지 먼저 정한다.**

## 7. 한글/영어 표기 규칙

이 저장소 노트는 한국어로 쓰이지만, Kubernetes/Docker 고유명사는 **영어 그대로 유지**한다
(다른 노트 파일들과 표기를 통일하기 위해서다).

- **영어 그대로 두는 것**: 리소스 종류(`Pod`, `Service`, `Deployment`, `StatefulSet`, `ConfigMap`,
  `Secret`), 상태/필드명(`Ready`, `Not Ready`, `Pending`, `OOMKilled`, `ClusterIP`, `RESTARTS`),
  컴포넌트 고유명(`CoreDNS`, `kube-proxy`, `HPA`, `metrics-server`), 실제 명령어(`COPY . .`,
  `RUN npm install`, `compose down`), 식별자(`db-0`, `vol_X`).
- **한글로 번역하는 것**: 그 외 전부 — 설명 문구, 상태 서술("사라짐", "가득 참", "재시작됨"),
  역할 설명("고정 IP + 부하 분산").

## 8. 접근성 태그

`<svg>` 바로 다음 자식으로 `<title>`과 `<desc>`를 넣는다 (스크린리더 및 검색 대응):

```xml
<svg ...>
  <title>한 줄 요약 (그림 제목)</title>
  <desc>이 그림이 보여주는 관계를 한두 문장으로 서술</desc>
  ...
</svg>
```

## 9. 노트에 삽입하는 방법

1. 파일명은 kebab-case로 `picture/` 폴더에 저장 (예: `picture/pod-deployment-service.svg`).
2. 해당 개념을 처음 설명하는 `##` 섹션 헤딩 바로 아래, 본문 시작 전에 삽입:
   ```markdown
   ## 5. Service — 왜 필요한가

   ![대체 텍스트(제목과 동일하게)](../picture/파일명.svg)

   본문...
   ```
   (`notes/` 안에서 참조하므로 상대경로는 `../picture/`.)
3. 워크북(`review01-workbook.md`) 같은 회상 훈련 문서에서는 **문제 바로 아래, 답 칸 위**에
   링크만 걸고 "정답 확인 전에는 보지 말 것"이라고 명시한다 (그림이 답을 미리 보여주지 않게).

## 10. 처음부터 끝까지 만드는 순서 (체크리스트)

1. 이 개념이 7번의 3가지 패턴 중 어디에 맞는지 정한다.
2. 등장할 박스 개수와 각 박스의 제목/부제 문구를 먼저 한글로 적어본다 (5단어 이내로 짧게).
3. 각 박스의 x, y, width, height를 계산한다 — 여백(1번), 간격(4번) 규칙을 지킨다.
4. 겹침이 없는지 좌표로 재확인한다 (특히 화살표 경로).
5. 색상을 배정한다 — 2번 팔레트에서 램프 2개 이내, 의미 있게.
6. `<title>`/`<desc>` → 배경 rect → `<defs>`(화살표 마커) → 박스들 → 화살표들 순서로 작성한다.
7. 완성 파일을 저장하고, 5번 섹션 방식대로 관련 노트 파일에 삽입한다.
